# pi-durable request control research

Read-only investigation, 2026-10-12. Source snapshot: `earendil-works/pi` commit `4270522473e677ddba7b093caa0064a3df51d459`. No runtime changes.

## Finding

**Yes, pi-durable plus a Dojo-owned pi-ai provider wrapper exposes the necessary request control. Stock durable configuration alone does not.** It supplies durable execution and model access; the gist's binary archive/tree/views and scheduling still need our implementation.

## Verified interfaces

- Durable's current generation hook is `beforeRequest`, not `buildContext`. It can replace request messages before every attempt, including recovery. Fixed extension prompt sections and a fixed selected tool registry can preserve the same prompt and tools for foreground and summarization. [Generation hooks](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/durable/src/harness/types.ts#L740), [request implementation](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/durable/src/harness/generation.ts#L207).
- Durable's persisted `ConversationStreamOptions` includes cache retention, headers, metadata, transport and retry options, but **does not expose `onPayload`**. The hook replaces messages, not the complete provider payload. [Options type](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/durable/src/harness/types.ts#L461).
- pi-ai exposes `onPayload` that can inspect **or replace** the complete provider payload. The Anthropic adapter awaits it and uses its returned parameters before sending. [Request option](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/ai/src/types.ts#L175), [Anthropic send path](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/ai/src/api/anthropic-messages.ts#L639).
- The documented provider-wide transformation mechanism wraps `ProviderStreams.stream` and `.streamSimple`. A Dojo-only provider wrapper can inject `onPayload` into both; durable invokes `runtime.models.streamSimple`. **Inference from these verified interfaces:** that wrapper can split the memory view into text blocks, remove automatic cache marks, and place the gist's four cache breakpoints precisely. Actual outgoing payload snapshots must prove the result; this has not been implemented. [Provider transformations](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/ai/README.md#custom-providers), [durable send](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/durable/src/harness/generation.ts#L431).
- Default Anthropic cache marks occur on system text, last tool, and last message; this is **not** automatically the gist's four line breakpoints. OAuth additionally injects Claude Code identity text into the system prompt. API-key mode avoids that OAuth-specific addition. [Payload construction](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/ai/src/api/anthropic-messages.ts#L1167), [message caching](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/ai/src/api/anthropic-messages.ts#L1483).

## Durability and lifecycle

- SQLite and JSONL persist conversations. State commits precede display; resume recovers pending tasks. Request IDs deduplicate input admission. Reset removes old entries from model context while retaining their archive. A provider session UUID survives reset and compaction. Thus one durable logical Dojo conversation can issue fresh per-message contexts without a new provider session identity each time. [Durable README](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/durable/README.md#persist-and-resume), [reset](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/durable/README.md#reset-and-handoff).
- Tool intent is committed before execution. After a crash, tools rerun only if marked replay-safe; other calls yield interrupted results. Replay-safe external effects still require their own idempotency. Durable storage therefore does **not** make desktop clicks, shell commands or outbound writes exactly-once. [Tools](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/durable/README.md#tools).
- Automatic durable compaction is a different algorithm from the gist and should be disabled/replaced for fidelity. The package explicitly calls itself experimental, with APIs changing without notice. [README](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/durable/README.md).

## Authentication and cost limits

pi-ai documents Anthropic Claude Pro/Max OAuth and OpenAI Sign in with ChatGPT alongside API-key auth. This is a technical integration claim, not proof of subscription terms, future availability or API-token billing equivalence. API-key Anthropic requests are the most direct way to reproduce and measure the gist's Anthropic cache behavior. Subscription use would need separate validation; token cost estimates are not evidence of cash savings under subscription billing. [OAuth providers](https://github.com/earendil-works/pi/blob/4270522473e677ddba7b093caa0064a3df51d459/packages/ai/README.md#oauth-providers).

## Proposed Dojo-only shape (inference)

Existing voice/socket/UI → local Dojo durable harness with SQLite → fixed Dojo tools plus zoom → custom pi-ai Anthropic provider wrapper. Keep the gist's archive/tree/view in Dojo-owned state, reset foreground model context for each user message, and implement summarization with the same system/tools and prescribed views. T3 can remain for every other project and agent, but this Dojo executor would no longer be a T3 run; its approvals, event presentation, credentials and tool bindings need explicit replacement. This is a migration proposal, not completed work.
