# Candidate B: session archive with a saved adaptive view

Keep T3 as the executor and provider owner. Add a Dojo-owned archive beside voice dispatch, with request sessions as its primary records. The archive survives T3 thread settlement and the visual stack's expiry. Summaries are replaceable indexes into exact recorded content.

Create a dedicated Dojo project/workspace through an established T3 project API after inspecting its installed schema. Never use `projects.ensureScratch` for this experiment. Put Dojo's AGENTS.md and memory MCP configuration only there. Store history and worker state under a separate Dojo memory directory. Do not change T3 defaults, provider-global instructions, other threads, or shared scratch files. Existing subscription credentials remain owned by T3.

Each request received after the previous run reaches a terminal state creates a fresh execution thread. Freeze its memory-view revision before adding the new request. Input received during an active run goes to that thread as steering and enters the same archive session. This deliberately changes `.scratch/speech/spec.md`'s present 30-second conversation reuse rule; visual expiry remains separate. Persist routing decisions and dispatch command IDs before contacting T3 so restart cannot misclassify steering as a new request.

Archive exact user text, assistant messages, exposed tool calls/results, and supported subagent reports as immutable leaves with permanent IDs, timestamps, source thread IDs and source event identities. Store large payloads as immutable blobs referenced by leaves. Streaming updates stay distinct journal events; a completed message references its ordered events. Never silently replace a full tool result with a display preview. Inspect T3's event and projection APIs first. If T3 supplies only truncated output, record the available bytes and an explicit completeness flag. Faithful retrieval promises only recorded content.

Build complete binary nodes over contiguous leaves, each with exactly two child IDs and the covered range. Request boundaries also form useful archive indexes. The saved adaptive view chooses nodes across sessions, keeping recent requests detailed and older requests coarser. Zoom returns two child records; leaf zoom retrieves exact bytes with UTF-8-safe pagination, cursor, total size and completeness. Date reads the leaf timestamp. Include IDs and framing in byte budgets; apply a separate model-token limit. Never truncate a source to satisfy a prompt limit.

A single background worker wakes on appended events, completed runs and startup recovery. Durable jobs name their input IDs and hashes. A dedicated T3 compaction thread selects a cheap model locally and disables side-effect tools if supported. Validate generated text and retry within a fixed limit. If this boundary is unsupported, leave nodes pending and expose exact references with bounded retrieval. State clearly that semantic compaction is unavailable. Do not manufacture summaries or bypass T3 with another provider client.

One owner holds an OS lock. Append and fsync journal records before acknowledging stream progress; checkpoint the replay cursor only afterward. Deduplicate by source event identity. Commit node/view/checkpoint replacements atomically and fsync their directory. Recovery removes an incomplete trailing record, preserves earlier durable records, and resumes queued jobs. An ambiguous remote dispatch is reconciled by its existing ID before retry. A reconnect uses the last durable sequence and backfills projections without duplicating leaves. No periodic idle polling is needed.

Replay tests cover steering races, duplicate events, disconnects, torn writes, job retries, view coverage and faithful paginated retrieval. Then run two independent live voice requests: the first stores a distinctive fact, and the second proves fresh-thread routing and retrieves its exact source through memory. Confirm both threads use the dedicated workspace and an unrelated T3 thread remains unchanged.
