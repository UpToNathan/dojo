# Architecture grounding for efficiency work

Dojo’s desktop combines a GPUI shell, a session-bus tray host, file-based theme publication, a Unix-socket voice coordinator with a native speech worker, and per-window GPU renderers. Work should follow existing owners and protocols: event-driven updates belong at the source that owns the state; renderer resource changes belong in GPUI/WGPU’s renderer lifecycle; battery policy belongs to desktop configuration and must preserve current capabilities. The audits identify recurring work and retained resources, but do not quantify future savings.

## Ownership and data flow

**Tray host → frame.** `TrayService::start` creates the `dojo-status-notifier` thread and owns its session-bus `Connection`, registration map, item/menu snapshots, command receiver, shutdown channel, and join handle (`src/tray.rs`). It implements both freedesktop and KDE `StatusNotifierWatcher` interfaces at `/StatusNotifierWatcher`; item registration identifies a service/object path and signals registered or unregistered events. The host currently drains UI commands, periodically reads item properties, then replaces the shared `Vec<TrayItem>`. `TrayHandle` is the UI-facing cloneable boundary: it snapshots items/menus and queues activate, context-menu, and `com.canonical.dbusmenu` events. `FrameView` receives that handle, currently samples it on each output’s own loop, and owns its `TrayImageCache`. The cache converts selected network-order ARGB32 pixmaps to `RenderImage`; it calls `Window::drop_image` when an icon changes or disappears. Keep D-Bus access on the host thread and GPUI image creation/drop on the window/UI side. Property and name-owner events can replace repeated full proxy construction, but preserve SNI/KDE compatibility and a slow reconciliation path for providers that miss or misorder events. Shutdown signals the host and joins it; dropping the service signals shutdown, so a blocking/event wait must remain interruptible.

**Theme and wallpaper publication.** `ThemeStore` owns the durable generation store under its configured root. `generate` writes a staged generation and renames it into `generations/<id>`; `commit` stages target symlinks plus `selection.json`, then atomically switches `current` through a symlink rename. `theme::apply` publishes generated files to owned external targets and reports target-level failures; it guards existing user files with a digest registry. The theme picker explicitly generates/applies only after user action. The wallpaper controller owns one transparent, input-empty background layer-shell window per display. It reads `current/wallpaper.txt`, validates an absolute existing file, reconciles windows on path/display changes, and retains the previous wallpaper on read/validation failure. It currently polls every 500 ms; a watch should observe the publication boundary and retain reconciliation for missed events. Do not bypass generation/selection atomicity or external-file ownership checks.

**Speech coordinator → native worker → T3.** `dojo-voice.service` starts `tools/speech/voice.mjs --serve`; CLI fallback starts the same coordinator behind `flock`, though current serve startup does not take that lock before preload/socket replacement. The coordinator owns the mode-0600 Unix socket, session/T3 client, chat/history state, subscriptions, capture state, and worker process. Socket commands are one JSON object per newline (bounded to 16 KiB, 45-second timeout); command errors return JSON and pass through centralized failure handling. On capture, the coordinator spawns `dojo-speech serve`, sends newline JSON `begin`/`finish`/`cancel` commands over stdin, and consumes newline JSON events on stdout. The Rust worker loads one selected model, announces `ready`, holds microphone capture only between begin and finish/cancel, transcribes and emits id-tagged events; the coordinator discards stale IDs, submits transcripts to T3, subscribes for run updates, and publishes bounded `SpeechEvent`s to the shell. The UI validates events and owns transient bubbles. Keep agent/session continuity in the coordinator; keep audio capture/model/inference in the native worker. Shutdown handles SIGTERM/SIGINT by canceling capture, ending worker stdin, closing the T3 client and socket server, clearing the timer, and unlinking the socket. Fix single-process ownership before changing startup or socket lifecycle; replace recurring checks with deadlines while preserving settlement and reconnect behavior.

**GPUI and GPU lifetimes.** Each `FrameView` owns its window-local state and currently starts a detached one-second task that probes host state, snapshots tray items and unconditionally notifies. Host-wide values therefore multiply with output count. Wallpaper windows and reserved-edge surfaces are separate windows/resources; do not assume multiple outputs share one renderer. GPUI’s `WgpuRendererCore` owns `WgpuResources` (device/queue, pipelines, atlas, buffers, optional path intermediate and MSAA textures). `render_frame` currently ensures those path textures for every frame, sizing them to the full target even if the scene has no paths; resize replaces the textures. This is the right owner for lazy path scratch allocation. GPUI `Window::drop_image` is the explicit path used by the tray cache to release image resources. Theme-picker previews currently pass original paths to `img`, allowing GPUI’s app-global cache to retain decoded images beyond picker close; preview bounds/lifetime need explicit ownership while Apply/Derive retain original bytes. Keep surface/window teardown, device recovery, antialiasing, wallpaper fidelity, blur, and all-output behavior intact unless measurements support changing them.

## Implementation constraints

Prefer change notifications plus a slow fallback for file, D-Bus, and host state; compare snapshots before notifying views. Share host-wide observation where ownership permits, while keeping per-output windows and input regions independent. Use deadlines for animation/settlement/expiry instead of permanent intervals. Preserve stable external protocols: StatusNotifierItem and dbusmenu, atomic theme generation and target ownership, newline JSON over the voice socket/worker pipes, native prewarmed speech capability, T3 event subscriptions, accessible speech UI, and wallpaper/blur appearance. Treat wluma capture cadence, Niri capture cropping, VRAM residency, energy savings, and release-build performance as open measurement questions from the audits, not established implementation facts.

## Starting points

- Tray and icon cache: `src/tray.rs`; frame ownership and notifications: `src/frame.rs`.
- Theme store/publication: `src/theme/store.rs`, `src/theme/apply.rs`; picker: `src/theme_picker.rs`; wallpaper windows: `src/wallpaper.rs`.
- Speech coordinator: `tools/speech/voice.mjs`, service unit: `tools/speech/dojo-voice.service`; worker protocol/model: `crates/dojo-speech/src/main.rs`; shell events/bubbles: `src/speech.rs`.
- GPUI WGPU resources: `vendor/zed/crates/gpui_wgpu/src/wgpu_renderer.rs`; renderer clients and per-window ownership: `src/frame.rs`, `src/wallpaper.rs`.
