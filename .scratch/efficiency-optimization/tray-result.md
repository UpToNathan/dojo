# Tray event ownership result

Implementation complete in `src/tray.rs`, with behavior verification delegated to the parent build owner. The existing dirty tray image-cache fix remains intact. `examples/tray_event_probe.rs` loads the private tray module and is designed for an isolated `dbus-run-session` bus.

The tray owner blocks on a condition variable instead of sleeping every 25 ms. Registration, scoped D-Bus signals, and bounded public commands wake it. There is no deadline with an empty registry. A nonempty registry retains a 30-second fallback for providers that omit change signals.

One cancellable task on zbus's existing executor owns five interface-specific signal streams. Each stream has a queue bound of eight. It filters item/menu owner and object path before notifying the host, and removes every match with AsyncDrop on exit. Signal notifications coalesce in one pending/refresh state. Shutdown sets a separate flag, bypasses the command queue, interrupts waiting, and checks the flag between items and commands. In-flight D-Bus requests retain the existing two-second method timeout, so shutdown cannot cancel a currently running blocking method call.

The public command queue has capacity 32 and reports busy/disconnected errors. Item proxies have owned addresses, pin a unique owner, and use CacheProperties::No so SNI New* signals trigger authoritative property reads. Open-menu proxies retain owner/path identity. Owner loss/replacement, passive/removal, and changed menu paths invalidate stale menu state. Menu refreshes do not call AboutToShow, preventing LayoutUpdated feedback; opening a menu prepares root and submenu levels as before.

Items are immutable Arc<Vec<TrayItem>> snapshots. Unchanged content keeps the same Arc. TrayPixmap stores immutable Arc<[u8]> pixel buffers, converted from Vec at the validated wire boundary. Snapshot, per-window image-cache, and callback item clones share those bytes. The churn fixture uses copy-on-write to deliberately change pixels. Tests assert shared pointer identity and literal network-ARGB to RGBA rendering bytes. Every subscriber receives a capacity-one channel; publication coalesces and removes disconnected subscribers. Worker exit drops subscriber senders, and new subscriptions after shutdown close immediately. The frame owner is responsible for subscribing and image-cache eviction.

Boundary validation rejects invalid D-Bus service/path registration addresses and malformed or oversized pixmaps. Stored pixmaps have at most 16 variants, dimensions at most 512 pixels on each side, and exactly width × height × 4 bytes. Rejected pixmaps log an error. Menu trees reject more than 16 levels or 512 total entries.

The fixture exercises registration, NewTitle, NewIcon, NewStatus passive/reactivation, PropertiesChanged invalidation, dbusmenu LayoutUpdated, owner removal, immutable snapshot identity, one-second idle property-read counts, command backlog shutdown, and subscriber closure. Unit tests cover subscriber coalescing/cleanup, wake shutdown, pixmap boundary behavior, registration parsing, shared watcher state, and menu command contents. The fixture must run on a private bus; it does not launch production tray applications.

No runtime counters or savings are claimed until the parent reports build/test and fixture results. Known limits: a relevant item signal refreshes all current item snapshots, and an open menu can be refreshed alongside an item change. These operations occur on events or the slow compatibility deadline; no per-item worker or generic desktop runtime was introduced.
