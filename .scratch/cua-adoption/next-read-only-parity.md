# Next read-only Driver parity work

Research date: 2026-10-12. Baseline is CUA commit `88aff7e5424e9ed45b93ded85eb4111472ca5190`, Driver contract `0.8.0`. This report inspected that checkout and Dojo source. It proposes implementation and acceptance work; it does not claim that the gaps have passed tests. Durable approval semantics and notification management remain discussion topics.

The [29-tool manifest](https://github.com/trycua/cua/blob/88aff7e5424e9ed45b93ded85eb4111472ca5190/libs/cua-driver/contract/manifest.json) defines the inventory. The read-only operations are `list_apps`, `list_windows`, `get_window_state`, `get_desktop_state`, `get_screen_size`, `get_cursor_position`, `clipboard_read`, `get_session`, `list_sessions`, `get_session_state`, `get_agent_cursor_state`, `parse_visual_regions`, and `verify_state`. Read-only annotations do not establish permission to disclose clipboard content, authenticated profiles or new sensitive capture scopes.

## Work that can proceed within current scope

| Priority | Contract | Existing behavior and concrete implementation reuse | Required acceptance |
|---|---|---|---|
| 1 | `list_windows` | `DesktopAdapter::context` in `src/bin/dojo-agent.rs` already sends Niri `Request::Windows` and `Request::Outputs`. Add the pinned typed `ListWindowsInput`/`ListWindowsOutput` projection, including positive PID validation, visibility filters, exact geometry and nullable stacking. Use authoritative same-render scene geometry where raw window records cannot establish bounds. | PID 0 and unknown arguments fail before compositor calls. Filter matches actual nested fixture windows. Off-screen workspace windows do not masquerade as visible. Fractional scale, nonzero output origin, tiled and floating geometry are correct. Unknown `z_index` is null, never array index or zero. Observation starts no input seat. |
| 2 | `get_screen_size` | The same context supplies output metadata. Reuse pinned `GetScreenSizeInput` and `ScreenSizeOutput`; project one explicitly selected desktop frame and its scale. Current Dojo coordinates are output-relative logical pixels, so choosing the first map entry would silently change the contract. State the primary-output selection rule and expose named-output metadata as extensions. | Empty/disabled outputs fail explicitly. Selection is stable under map reordering. Rotation, fractional scale and multiple-output layouts have literal expected values. Screen dimensions and captures/actions share the documented coordinate frame. No seat creation or idle renewal. |
| 3 | `list_apps` | Upstream Linux `ListAppsTool::invoke` combines `proc_fs::list_processes`, `installed_apps::list_installed_apps`, and `wayland::list_windows_dispatch`. Dojo `src/launcher/catalogue.rs::Catalogue::discover/from_roots` already parses XDG entries, handles precedence and exposes `Application`. Move the existing catalogue into a library module if shared; keep GPUI out of the discovery API. Reuse coherent upstream discovery/merge logic and its fixtures instead of a second hand-written desktop parser. | Installed-only entries use PID 0 and running false. Hidden/NoDisplay and desktop-specific filtering match pinned fixtures. Duplicate desktop IDs obey XDG precedence. Running apps with no top-level window still appear. Ambiguous executable basename matches do not establish an authorization identity. `Exec` is never executed. Symlink recursion and huge directory inputs remain bounded. |
| 4 | `get_session` / `list_sessions` | `service.rs::Session`, `Session::active/expire`, and `Message::Status` already own lifecycle, browser and capture state. Current status returns only seat name and active boolean. Reuse pinned `SessionOutput` and `ListSessionsOutput`, with connection lease visibility. Expose the existing implicit connection before introducing named session lifecycle semantics. Upstream core `session_tools.rs::GetSessionTool/ListSessionsTool` provides pagination, label sanitization and output fixtures, but its global registry is not Dojo's session owner. | Two MCP connections cannot read each other's summaries. Reads do not spawn a seat, extend leases, renew browser ownership, or clear unknown-effect barriers. Status contains no capture bytes, URLs, prompts or file paths. Time fields derive from the real service timestamps. Limit 1..100 and pagination are validated. Ended/expired state is accurately reported, never revived by read. |

## Larger read-only gaps

`get_cursor_position` must read the real human OS pointer. `get_agent_cursor_state` must read the requesting session's agent cursor and motion. Current Niri `InputCoordination` contains revision and human-owned windows, without pointer coordinates, and service status contains no theme/playback/motion. Add compositor-owned read APIs before claiming these rows. Never return the agent position as the human position. Pinned `CursorPositionOutput` permits an explicit unavailable result, which is an honest intermediate contract but not completed supported-host parity. Test separate human/agent locations, output transforms, lock, movement completion and cross-session denial. See pinned [cursor_tools.rs](https://github.com/trycua/cua/blob/88aff7e5424e9ed45b93ded85eb4111472ca5190/libs/cua-driver/rust/crates/cua-driver-contract/src/cursor_tools.rs).

`get_window_state` needs exact AT-SPI top-level correlation. `desktop_accessibility` delegates to `crates/dojo-accessibility::observe` and returns an application-scoped tree with display labels. `desktop_observe` provides exact native window captures. Combining them without identifying the accessibility top-level would misrepresent unrelated windows as one exact snapshot. Add correlation and bounded snapshot storage first. Pinned `GetWindowStateInput` also specifies query, tree format, timeout, size limits and `since` deltas. Tests must include two windows in the same process, duplicate titles, partial trees, password fields, stale deltas and process restart. Read-only element tokens must not acquire effect authority. See [windows.rs](https://github.com/trycua/cua/blob/88aff7e5424e9ed45b93ded85eb4111472ca5190/libs/cua-driver/rust/crates/cua-driver-contract/src/windows.rs).

`parse_visual_regions` needs a verified inference backend and pinned actual model bytes. The immutable capture mechanism exists, but schema and artifact references do not implement OCR/icon inference. Retain capture digest, preprocessing transform and exact output mapping. No model output grants input authority. See [cua-perception](https://github.com/trycua/cua/tree/88aff7e5424e9ed45b93ded85eb4111472ca5190/libs/cua-driver/rust/crates/cua-perception).

## Existing partial equivalents, not proven aliases

- `desktop_context` partly covers `list_windows` and `get_screen_size` through a richer Dojo-specific response. It has no pinned output adapter or input filters.
- `desktop_observe` and `desktop_screenshot` cover visual observation, with Dojo capture identity and named-output coordinates. They do not establish the exact `get_desktop_state` frame/schema contract.
- `desktop_verify` implements bounded tri-state predicates. Native window and owned-browser evidence works; native accessibility predicates stay unknown without exact window correlation. `include_screenshot=true` is unsupported, while upstream permits final uninterpreted screenshot evidence.
- `desktop_accessibility` covers application-scoped AT-SPI reads, not exact `get_window_state`.
- `desktop_browser_observe` / `desktop_browser_inspect_ref` implement session-bound browser reads. These are useful Dojo operations beyond the 29 public Driver names, with their own identity and sensitive-profile restrictions.
- `desktop_release` performs cleanup. It is not a full named-session `end_session` alias, and teardown is not a read-only operation.
- `get_session_state` is deprecated upstream legacy capture-policy access. Dojo has no matching legacy public capture-scope session owner. Do not fabricate a successful compatibility response.

These facts come from `src/bin/dojo-agent.rs`, `src/bin/dojo-agent/service.rs`, `src/bin/dojo-agent/browser.rs`, `src/bin/dojo-agent/screenshot.rs`, `crates/dojo-accessibility/src/lib.rs`, and `vendor/niri/niri-ipc/src/lib.rs` as inspected on the research date. Local source is work in progress; provenance tooling must record final hashes after implementation.

## Deferred for discussion or separate prerequisites

Do not add clipboard content reads before the approval/privacy discussion. They can disclose secrets even though upstream marks the operation read-only. Clipboard type enumeration may be separable after its own privacy contract is chosen. Do not add consumer browser profile access, content history, durable permission grants, canonical artifact deletion policy, or notification behavior here. Mutating Driver operations stay on the existing admitted routes; this report grants no additional mutation permission.

Keep Rust as execution owner and Pi as the only scheduler and durable conversation/task owner. Discovery and status adapters need no background poller or new database. Each newly copied source file and fixture must enter the pinned provenance ledger before it is advertised as parity.
