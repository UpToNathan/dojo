# Perception grounding: capture, service and Pi

Scope: source exploration for read-only `parse_visual_regions` against immutable images. This report does not propose durable approvals, grants, or dependent mutations. Upstream reference is `88aff7e5424e9ed45b93ded85eb4111472ca5190`; local source was read on 2026-10-12. The worker implementation is covered by a separate explorer.

## Components found

- `CaptureAuthority`, `crates/dojo-computer/src/lib.rs:475`, owns the process-wide `CaptureService` and a separate map of session-bound scope/frame evidence. Its config at line 482 sets a 30 second TTL, 32 captures, 64 MiB total encoded storage, 32768 maximum width/height, and 128 MiB maximum decoded image bytes.
- `CaptureSession`, `crates/dojo-computer/src/lib.rs:515`, owns a private `CaptureBinding`. It exposes publication, scope lookup, action admission, retirement, and model decoding. It exposes no method that returns PNG bytes to another crate.
- `CaptureService`, `crates/dojo-cua-primitives/src/capture_registry.rs:1084`, creates runtime/session generations and exposes non-consuming `read_for_perception` at line 1171. It distinguishes this operation from consuming `admit_action`.
- `PerceptionCapture`, `crates/dojo-cua-primitives/src/capture_registry.rs:573`, contains immutable stored pixels and metadata. `png_bytes()` at line 580 returns `Arc<[u8]>`. Digest, encoded dimensions, target, creation and expiry are readable. Its action transform accessor at line 596 is restricted to the defining crate.
- `Session`, `src/bin/dojo-agent/service.rs:293`, owns the live `CaptureSession`, disconnect flag, capture/seat leases and external-effect recovery state. The service loop at line 1271 shares one capture authority across connections and serializes request handling.
- `ActiveSession`, `src/bin/dojo-agent/service.rs:93`, is the MCP adapter's Unix socket connection. `Message` at line 37 is its strict tagged wire enum. No perception parse message exists.
- `DesktopAdapter`, `src/bin/dojo-agent.rs:211`, owns that connection; `DesktopServer::desktop_observe` at line 609 emits metadata plus the original PNG as MCP content. `desktop_decode_model` at line 554 is the existing read-only session lookup route.
- `openDesktopExtension`, `tools/speech/desktop-extension.mjs:81`, registers the discovered MCP schemas directly as sequential Pi tools. `desktopReplay` at line 8 is an explicit allowlist, separate from MCP annotations.
- `ModelDecode`, `ModelSource`, `CaptureSession::decode_model`, `crates/dojo-computer/src/model.rs:36,45,86`, bind parsing to a live capture digest and dimensions. This parser does not perform perception inference.
- `computerModelBridge`, `tools/speech/computer-model-bridge.mjs:32`, asks Rust to decode completed foreground model text and records model provenance in a Pi action intent. Transport and usage stay with pi-ai.

## Flow

1. Pi discovers `dojo-agent` through `DesktopMcp.open`, `tools/speech/desktop-extension.mjs:18`. It initializes MCP and fetches `tools/list`. Registration pins a fingerprint of tool names and input schemas. Reconnection rejects a changed catalog rather than interpreting it under the old registrations.
2. `runtime.executeDesktopTool`, line 108, reserves one durable attempt before transport. The default maximum is 1000 calls, including reads. It routes abort to connection closure. `desktop_observe` is explicitly replay safe, so this call does not preemptively consume Pi's current capture marker.
3. `DesktopServer::desktop_observe`, `src/bin/dojo-agent.rs:609`, authorizes the requested scope and runs the blocking adapter. `DesktopAdapter::observe`, line 267, validates the scope, refreshes connection state and opens a service session if necessary. Connection hello pins protocol version 4 and the loaded operator policy digest. A display name supplied by the client is not the capture's private session identity.
4. `Session::observe`, `src/bin/dojo-agent/service.rs:345`, checks cancellation, resolves current frame, captures PNG, resolves current frame again, and requires identical identity/geometry/ownership. If the backend supplies scene frame evidence, that must also equal the current frame. It checks cancellation again before publication.
5. `capture_image_cancellable`, `src/bin/dojo-agent/screenshot.rs:171`, uses compositor scene capture for positioned windows. Output/region captures use the native backend by default, or the explicitly selected grim backend. The capture paths carry cancellation and a five second deadline. In the grim path timeout/cancellation kills and waits for the child. Image resampling is cancellable and happens before publication.
6. `CaptureSession::publish`, `crates/dojo-computer/src/lib.rs:534`, validates scope/frame consistency, derives the image-to-output affine transform from the actual delivered dimensions and logical frame, and publishes the PNG under its private binding. `CaptureRegistry::store`, `crates/dojo-cua-primitives/src/capture_registry.rs:699`, validates PNG decoding with limits, verifies actual dimensions, validates transform extent, hashes exact encoded bytes with SHA-256, sets monotonic expiry and evicts oldest entries to fit count/byte bounds. It stores `Arc<[u8]>`.
7. The returned `Observation`, `crates/dojo-computer/src/lib.rs:450`, contains capture ID, digest, timestamp, TTL, delivered dimensions, complete frame, axis scales, actionable status and coverage. The service additionally supplies scene frame serial and base64 of the same PNG. The MCP adapter removes the base64 field from metadata and sends it in an `image/png` content block. Pi records this capture ID and clears recovery-required after a successful observation. Images pass through unchanged.
8. The closest existing perception route is model decoding. `desktop_decode_model` validates input, requires an existing live connection, and sends `Message::DecodeModel`. `Session::handle`, `src/bin/dojo-agent/service.rs:546`, calls `CaptureSession::decode_model`. That method uses `scope` plus `CaptureService::read_for_perception` under its private binding; it never calls action admission. It constructs an identity `ModelView` from retained dimensions and digest, invokes the Rust parser, and returns `authorized:false` and `capture_consumed:false`.
9. `CaptureService::read_for_perception` reaches `CaptureRegistry::read_for_perception_bound`, `crates/dojo-cua-primitives/src/capture_registry.rs:785`. The registry lock covers expiry and exact binding comparison. The method clones retained immutable data without removing the registry entry. Invalid, expired, unknown and mismatched generations fail. A successful read does not extend expiry.
10. In contrast, `CaptureSession::admit`, `crates/dojo-computer/src/lib.rs:651`, independently validates prediction digest/parser version, the exact current frame, exact window and coordinate bounds, then calls consuming `admit_action`. That method is unnecessary for a perception reader. Region results are not part of any existing admission API.

## Boundaries

The missing image seam is precisely between `CaptureSession` and a perception caller outside `dojo-computer`. `CaptureAuthority.captures` and `CaptureSession.binding` are private. The underlying `CaptureService::read_for_perception` and `PerceptionCapture::png_bytes` already implement immutable, non-consuming access, but neither PNG nor a perception handle is exposed through `CaptureSession`. A caller inside `dojo-computer` can resolve the ID with `self.binding` and hand off immutable bytes, digest and encoded dimensions. An external worker integration needs a session-owned public resolver or a session method that performs that handoff. It must not require caller-supplied session binding, an action admission, or fresh screenshot bytes. This identifies the missing boundary, not a finalized interface design.

The service and MCP routes currently have no parse request. The existing decode route establishes how a strictly parsed capture ID can reach the owner without creating a seat. The upstream declaration describes one registered capture ID and optional model-neutral kind/confidence/count controls, denies extra fields, and marks the operation read-only, idempotent and closed-world. It does not accept arbitrary PNG content or paths.

Policy enforcement is independent of capture storage. `policy::authorize`, `src/bin/dojo-agent/policy.rs:16`, loads `DOJO_DESKTOP_POLICY` when configured; absent configuration currently allows dispatch. The file must be regular, owned by root/current UID, small and not group/world writable. `DesktopPolicy::authorize`, line 55, reloads and compares its digest before applying `HostPolicy`. The shared service's `authorize_message`, `src/bin/dojo-agent/service.rs:74`, maps each wire operation to a tool name. The read-only decode operation is covered there. A new message would need an explicit mapping. Registry reads themselves perform no disclosure policy check.

Pi annotations do not decide replay behavior. An unlisted parser name falls into `desktopReplay(...)=unsafe`, clears `captureId` before sending and is refused while an external effect is unresolved. Successful image-bearing results from tools other than observation/action also clear the marker, `desktop-extension.mjs:156`. A metadata-only parser explicitly classified as a read would preserve the existing capture state under this code. The underlying Rust session currently blocks only the enumerated mutations while `external_unknown` is set, `service.rs:500`.

The output coordinate boundary also matters. `PerceptionCapture` exposes image dimensions but no public action transform outside its crate. `Observation.frame` and axis scales already describe delivered pixels to output-relative logical coordinates. `ModelView`, `crates/dojo-computer-models/src/lib.rs:36`, can represent crop/resize mathematically; the live `CaptureSession` model adapter deliberately supplies only identity preprocessing named `unchanged_dojo_delivered_png/1`. Detector-internal resizing must retain its own inverse mapping if its regions are to refer to these original delivered pixels. Neither the current Pi bridge nor current decode request accepts a resized/cropped external model view.

## Non-obvious things

- Lookup freshness and byte lifetime differ. `PerceptionCapture` clones an `Arc`; `png_bytes()` clones it again. TTL expiry, eviction or retirement drops registry-owned references, but cannot revoke bytes already borrowed by a worker. Subsequent lookup fails. A worker needs its own deadline/cancellation and a deliberate completion freshness rule; those are not supplied by the byte getter.
- The capture TTL is per publication. `Session.last_observation` keeps a connection active until 30 seconds after its latest observation, and observation does not renew seat idle time. Older captures can expire sooner while the connection remains active. Read-only decoding does not renew either lease.
- `CaptureSession::retire`, `lib.rs:735`, deletes captures under the old binding and advances its generation. Drop performs retirement too. Release, low-level input, capture input and browser lifecycle transitions retire capture authority. Disconnect removes the owning session. Service shutdown drops all sessions. Random registry namespaces prevent reuse of old IDs after restart even though the runtime counter begins anew in a new process.
- `DesktopAdapter::refresh_connection`, `dojo-agent.rs:219`, drops an inactive or failed status connection. A read cannot revive an expired capture by reconnecting. `Session.active` depends on existing seat/browser/capture leases, not connection existence alone.
- Disconnect detection runs independently from the serialized service loop. `connection`, `service.rs:1182`, continues reading while a request executes and sets the atomic cancellation flag on EOF/error. Its response writer suppresses replies after cancellation. The main loop later removes the session. A blocking worker cannot rely only on that later removal.
- The service loop handles all client operations synchronously. Expiry/pruning run between requests. Adding a long inference call directly here would delay other sessions and maintenance even though a connection reader can still set cancellation. A bounded worker design must account for this actual owner.
- Exact-window observations are marked actionable, but full-output/region observations are already immutable read-only captures. Perception need not demand actionability. Cropped window pixels can include occluding surfaces; the observation's coverage statement says so.
- Model provenance is prediction metadata. `ModelSource` has profile/parser/raw/digest/call ID; admission validates digest and parser version. A parsed region does not automatically create browser refs, element tokens or capture action authority.
- The compatibility screenshot tool does not register an immutable capture and explicitly invalidates Pi's current capture marker when its image arrives. It is not a substitute for this lookup.
- Provider request projection preserves retained image blocks and omits older ones. `projectDesktopImages`, `tools/speech/image-retention.mjs:3`, replaces images beyond the configured count with text in a copied request; it does not resize pixels or edit canonical entries. `pi-runtime.mjs:60` defaults to eight retained images but permits zero. This setting does not invalidate the current capture ID, so a live decoder binding alone does not prove that the provider saw its image.
- Runtime `stop` and `close`, `tools/speech/pi-runtime.mjs:230,245`, close the desktop connection and invalidate durable capture state before waiting on Pi work. `DesktopMcp.close`, `desktop-extension.mjs:66`, rejects pending calls, sends SIGTERM to the MCP child, then escalates to SIGKILL after a default 250 ms. A tool timeout defaults to 30 seconds and follows that same connection cleanup path.

## Open questions

The exact worker cancellation/resource/usage and artifact interfaces are outside this slice. No running perception worker is wired into the inspected session route. A decision is still needed about a parse that starts before capture expiry and finishes after it, and about held-byte accounting beyond registry-owned storage. Current APIs answer whether a lookup is valid now; they do not provide revocable byte leases or a completion freshness policy.

Whether public output contains delivered-image boxes, output-relative logical boxes, both, or the precise upstream contract result shape must be resolved with the worker/contract exploration. Current capture facts support exact delivered-image binding and server-derived logical mapping; they do not prove detector preprocessing equivalence or inference parity. Durable approval and dependent mutation policy remain outside this investigation.
