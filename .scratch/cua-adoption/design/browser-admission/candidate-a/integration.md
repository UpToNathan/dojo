# Integration map and acceptance plan

## Source ownership and callers

- `vendor/niri/src/niri.rs`: read explicit operator enrollment at startup and pass it into admission state; do not silently enable enrollment.
- `vendor/niri/src/external_admission.rs`: own lazy child activation, pidfd/control-channel monitoring, process/session/peer bindings, pending writer scopes, final actor write, and teardown ordering. Keep wire structs private and parse bounded messages here.
- `vendor/niri/src/ipc/server.rs` and `vendor/niri/src/agent_input.rs`: capture kernel credentials and process generation when a connection is accepted; carry immutable binding through `ClientCtx` and `AgentSeat`; revoke peer-owned pending writers when that connection/seat is destroyed.
- `src/bin/dojo-agent/service.rs`: replace its self-PID startup-pin requirement with the compositor-issued activation capability. Preserve existing policy checks, one-use capture and episode retirement, browser lifetime, cancellation, and unknown session barrier.
- `src/bin/dojo-agent/browser.rs`, `browser_owned.rs`, and `vendor/cua/driver/.../browser/read.rs`: retain exact page target, native window/process generation, browser-root and endpoint-owner distinctions; no relaxation of current fresh read rebind.
- `crates/dojo-external-admission/src/broker.rs` and `src/bin/dojo-agent/browser_mutation.rs`: preserve compositor authentication, exact `/devtools/page/{target}` upgrade, one FD transfer, no retry after ambiguous handoff, and typed receipt correlation. Replace only the static recipient with the generation-bound activation endpoint.
- `src/bin/dojo-agent.rs`: retain typed MCP request and `pi-ai` transport. Add a typed Pi intent correlation field only if the current Pi persistence path can supply it as committed state; never trust a model argument as proof.
- `tools/speech/desktop-extension.mjs`: continue pretransport durable reservation and unknown barrier. Do not clear it on registration, restart, fresh observation, or missing receipt. Add settlement only if an existing accepted mechanism supplies the authority and semantics.

The Niri actor is the sole writer and owner of pending descriptors. The service owns the upgraded page socket only until the successful single transfer. Pi owns durable scheduler/replay/recovery state; `pi-ai` owns transport. There is no new Rust durable store, scheduler, Python service, or installed system change in this candidate.

## Revocation ordering

Every pending writer is indexed by activation, session, peer and target. On control-channel EOF, pidfd exit, IPC peer close, seat expiry, or compositor shutdown, the event actor first marks the corresponding generation/peer/session dead, then removes each writable source, shuts down and drops its FD, retires pending counts, and only then acknowledges revocation or destroys the activation. The ready callback checks the same liveness record immediately before the one nonblocking write. Because teardown and send run on one actor, whichever actor event runs first decides: teardown first means no write; send first means outcome unknown and the unresolved-target barrier remains. No later receipt can convert an accepted/partial write into refusal.

Cancellation before FD transfer is locally effective. After FD transfer it must reach the compositor over the live activation capability. If that channel is already gone, pidfd/control-channel loss drives teardown. A lost cancellation response is unknown. This ordering is a design contract to prove, not existing behavior.

## Process-generation and peer/session binding

Niri launches the child from the operator-enrolled artifact and observes PID/start plus pidfd itself. It gives the child one non-cloneable private control endpoint containing a fresh activation generation and compositor generation. The service cannot choose those values. IPC accept captures kernel peer credentials and resolves start time before async work; the immutable owner is attached to the connection, seat, session registration, and broker message. The broker's kernel sender credentials must match the registered child generation, and the requested peer must map to that same activation/session. Caller JSON cannot choose owner credentials, peer membership, or activation.

A new child generation gets a new capability, session table, read episodes, captures, controller, and writer namespace. Reconnection or a new generation does not inherit old captures or clear Pi/Niri uncertainty. Same-UID checks remain an additional boundary condition only; they are not the trust enrollment.

## Exact browser proof and exclusive handoff

Preserve current fresh `take_navigation_binding` checks: exact selected page target, exact native window and process generation, browser-root/native-client relation, allowed loopback endpoint, endpoint owner PID, active page, and fresh rebind. Keep native window PID, browser root PID, and listener PID distinct. The broker authenticates the compositor before upgrading precisely `/devtools/page/{target}`, validates the handshake and bounded headers, and transfers exactly one upgraded stream FD. It drops every broker-owned writer handle after transfer. Niri validates the endpoint against the browser identity and uses only its actor-built `Page.navigate` payload. No general CDP command, direct service-side write, WebSocket library queue, or retry after ambiguous transfer is introduced.

The handshake and `/proc` checks do not prove that no clone or buffered mutation exists. The trusted broker implementation must retire prior sockets, avoid cloning writable descriptors, and not send before transfer. Real isolated Chromium proof must establish this route's actual identities; if Chromium/Nix creates split identities the current exact-PID path must refuse until a separately proved adapter exists.

## Red/green verification on inactive `dojo-tests`

Use the existing nested `dojo-tests` fixture route and add only disposable test artifacts under the nested test tree. Do not touch installed compositor files. Keep the fixture inactive outside each controlled run; assert fixture inbox effects and receipts directly, not helper self-report.

1. **Activation provenance and generations.** Red: a same-UID process, a service-supplied PID/start, a forged peer ID, a stale capability, or a second process using a copied token cannot register or submit. Green: Niri-launched enrolled child registers through inherited capability; kernel peer PID/start, activation generation, compositor generation, and seat peer all agree. Kill the child, start a new generation, and prove the old FD/session/capture cannot submit.
2. **Lazy lifetime/idempotence.** Red: concurrent first requests do not spawn two services; altered policy digest or unenrolled artifact fails closed. Green: no child before demand, one child during demand/grace, reconnect uses the same live generation, and restart creates a new generation without clearing unknown state.
3. **Exact page/window/native binding.** Red: wrong page target, target swap after observation, stale capture, wrong native window, changed browser/native process start, changed endpoint listener owner, split unsupported browser-root/native identity, or wrong compositor generation never yields a fixture inbox frame. Green: actual isolated Chromium selected page maps to the captured native window and verified endpoint; only its exact page receives one masked `Page.navigate` frame. Preserve `native PID != listener PID` cases if supported by current verifier; test each role explicitly.
4. **Exclusive writer transfer.** Red: second FD, duplicated descriptor, malformed/truncated ancillary data, unrelated FD, wrong page handshake, extra protocol/extensions, pre-transfer write, or attempted retry cannot produce a second effect. Green: exactly one upgraded socket crosses once, broker writer closes immediately, Niri constructs the only allowed frame, one frame is observed, and intent reuse is rejected.
5. **Takeover and final writer.** Red: process a human takeover/coordination revision before actor dispatch and prove no frame/effect. Green: without takeover, actor dispatch produces exactly one frame; a takeover after accepted write is reported unknown and never replayed. Exercise Niri's actor ordering, not a service-side timing assertion.
6. **Cancellation after FD handoff.** Red: close activation channel, kill service, close IPC peer, expire seat, and replace activation with a pending writer; before actor send, fixture observes no frame, FDs/writer sources are retired, and teardown acknowledgement follows retirement. Green: cancellation response is emitted only after revocation; if actor send wins first, result and Pi state remain unknown. Add deterministic barriers to force both event orders.
7. **Loss and uncertainty.** Red: drop admission receipt after descriptor transfer or crash service/compositor after a possibly accepted write; no retry is sent from a new service generation and registration/read observation cannot clear barriers. Green: Pi keeps its durable unknown reservation across MCP timeout and service/compositor restart. Explicit recovery settlement is not testable until an accepted authority and clear operation are identified; do not write a test that assumes observation settles it.
8. **End-to-end route.** Red: MCP request before committed Pi reservation, model-supplied fake intent ID, wrong capture, policy denial, or service restart after ambiguous handoff produces no replay. Green: on inactive nested Chromium, Pi commits reservation, MCP reaches lazy Niri activation, Rust retires the exact read episode, Niri writes one frame to the exact page, and the receipt correlates to Pi's committed intent while `pi-ai` remains transport owner.

Run the specific Rust unit/integration targets and existing nested socket proof harness from `devenv`, followed by the live inactive-`dojo-tests` Chromium-to-MCP run only after the unit gates pass. Archive command, compositor/service generations, exact browser/native/listener/page/window identities, fixture observations, Pi durable state before/after, and the final receipt. Source tests and the existing fixture socket proof do not substitute for the real Chromium-to-MCP route. No tests or live route were run during this design task.
