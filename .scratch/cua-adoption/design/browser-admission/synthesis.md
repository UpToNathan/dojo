# Browser admission synthesis

Use candidate B's fixed-recipe launch attester and scoped actor registration as the base. Parent review agrees with the cross-judge's 16/18 versus 11/18 result. The strongest difference is explicit launch provenance: the selected live attester executes one reviewed ELF, argv, environment and descriptor recipe. An arbitrary invocation of the same image cannot enroll itself. Niri remains the sole final writer; the service retains captures, browser episodes and sessions; Pi retains durable intent and uncertainty.

Graft candidate A's broad inactive-workspace proof matrix and exact Chromium/MCP ownership map. Retain B's per-session ingress, separate cancellation control, kernel credentials, invalidation before FD/source cleanup, and conservative uncertain outcomes. Both proposals require a real route proof. Descriptor uniqueness is a trusted implementation obligation, not a kernel guarantee.

Reject path/hash-only self-enrollment, arbitrary seat or same-UID enrollment, an async mutable Niri method that holds the actor while waiting, and registration or observation clearing uncertainty. No approval or recovery-clear semantics are introduced. Installed launcher/compositor configuration remains a separately reviewable deployment.

The first implementation unit is a source-only fixed-recipe child launch prototype. It must load immutable reviewed configuration, preserve an opened ELF identity, clear ambient environment, deliberately inherit one private channel, authenticate child messages with kernel credentials, and expose attestation only for a child the attester actually owns. Test the same-image/arbitrary-invocation counterexample before adding compositor enrollment. Later units add process/peer/session registration, queued descriptor revocation, and the real Chromium-to-MCP route. Every unit must pass before the next begins.

Source and artifact provenance follow CUA baseline `88aff7e5424e9ed45b93ded85eb4111472ca5190` and the existing lockfiles. This is a design selection and implementation sequence, not a verified parity or deployment claim.
