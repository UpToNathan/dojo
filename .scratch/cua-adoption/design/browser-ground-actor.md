# Browser admission actor grounding

This is source inspection for architect Phase A on 2026-10-12. No code, tests, installed configuration or running desktop changed. The governing contract is [ticket 16](../issues/16-side-channel-admission.md), [the adoption spec](../spec.md) and [the existing decision](decision.md). Pi remains the sole scheduler and durable conversation owner. A lazy Rust desktop service is an execution and transport owner.

## Answer

An operator-enabled lazy service can become the trusted CDP bootstrap broker through a narrow registration protocol. Existing AgentSeat ownership cannot establish that trust: Niri currently stores a connection-local numeric peer ID, without an authenticated owner PID, UID or process start time. Adding peer credentials would establish which process owns a seat connection, but would still leave operator authorization, exact browser page/window correlation and exclusive write ownership as separate obligations.

The safe change is to replace the static broker process-generation pin with an equally narrow operator-authorized binding for the running Rust service. Do not replace it with “owns any agent seat” or “same UID.” An operator-authorized executable identity or launcher-attested process generation would be a new trusted boundary, requiring its own design and proof. Seat credentials can bind the registered broker to its exact live seats after that boundary admits it.

## Current call chain and proofs

1. [Niri startup](../../../vendor/niri/src/niri.rs:2633) reads `DOJO_EXTERNAL_ADMISSION_SOCKET`, `DOJO_EXTERNAL_TRUSTED_BROKER_PID` and `DOJO_EXTERNAL_TRUSTED_BROKER_START` once. Failure logs that admission is disabled. [Admission start](../../../vendor/niri/src/external_admission.rs:212) verifies the pinned process start time, binds a mode-0600 Unix datagram socket, makes it nonblocking and enables `SO_PASSCRED`. There is no registration/rebinding operation for a service that starts later or restarts.
2. [IPC connection creation](../../../vendor/niri/src/ipc/server.rs:177) allocates `next_agent_peer`; [ClientCtx](../../../vendor/niri/src/ipc/server.rs:56) carries that number. It does not read `SO_PEERCRED`. [AgentInput dispatch](../../../vendor/niri/src/ipc/server.rs:355) inserts an event-loop idle callback with the connection's peer. [Seat creation](../../../vendor/niri/src/agent_input.rs:219) stores that peer and returns it to the client. [AgentSeat](../../../vendor/niri/src/agent_input.rs:37) carries no process credentials. [ClientCtx drop](../../../vendor/niri/src/ipc/server.rs:66) schedules seat destruction. The peer identifies a connection and its seat, rather than an authenticated process or operator-selected broker.
3. The ordinary service [starts lazily](../../../src/bin/dojo-agent/service.rs:172), launching its own executable with `--service` when the per-compositor service socket is absent. The navigation [preflight](../../../src/bin/dojo-agent/service.rs:637) currently requires explicit enablement and requires the environment's pinned PID/start to equal the service itself. It consumes capture authority, revalidates the browser binding against capture PID/start/window, ensures a seat controller, and mints internal intent/grant IDs. These IDs are Rust authority records, not a demonstrated authenticated durable consent record. [NavigationGrant documents that distinction](../../../src/bin/dojo-agent/browser_mutation.rs:8).
4. The browser [take_navigation_binding](../../../vendor/cua/driver/crates/cua-driver-core/src/browser/read.rs:421) requires the native-client and browser-root PID to match, exact binding quality, allowed endpoint class, endpoint owner PID, active selected page and a fresh read-only rebind. It closes the read-only episode before returning a binding. Split native-client/browser-root bindings are explicitly refused. [Service dispatch](../../../src/bin/dojo-agent/service.rs:731) invokes [browser_mutation::dispatch](../../../src/bin/dojo-agent/browser_mutation.rs:22), which builds a typed `NavigateIntent` and calls `broker::navigate_cancellable`.
5. [Broker preparation](../../../crates/dojo-external-admission/src/broker.rs:59) checks cancellation, bounds target/lifetime/payload, creates a private reply directory/socket and authenticates the compositor using a nonce probe plus `SCM_CREDENTIALS` and the compositor PID/start from capture. [Upgrade](../../../crates/dojo-external-admission/src/broker.rs:254) requests precisely `/devtools/page/{page_target}`, checks the WebSocket accept key and headers, rejects unsolicited extension/protocol negotiation and reads only through the HTTP header terminator. [Transfer](../../../crates/dojo-external-admission/src/broker.rs:309) sends one TCP FD through `SCM_RIGHTS`; the caller drops its only socket owner immediately afterward. Cancellation is checked before transfer. After transfer, the broker waits for an authenticated bounded admission receipt and cannot promise cancellation or rollback.
6. Niri [receive](../../../vendor/niri/src/external_admission.rs:532) uses `MSG_CMSG_CLOEXEC`, rejects truncation, malformed/unrecognized ancillary data, duplicate credentials and more than one FD. A zero-FD packet is allowed only into the probe path. [Per-packet authentication](../../../vendor/niri/src/external_admission.rs:256) checks kernel sender PID against the static broker pin, effective UID equality and fresh process start time. The `peer` inside the JSON request is supplied by this trusted broker; Niri does not compare it to authenticated IPC owner credentials.
7. [Registration](../../../vendor/niri/src/external_admission.rs:294) bounds pending writers, validates typed fields, rejects an unresolved window and calls `resolve_external_target`. [Endpoint verification](../../../vendor/niri/src/external_admission.rs:450) checks process start, stream/TCP type, loopback IPv4 addresses, one matching 127.0.0.1 listening inode in `/proc/net/tcp`, and ownership of that inode in the authoritative browser PID's FD table. It then rechecks process start. This proves ownership of the listening endpoint at registration. It does not independently prove the transferred connection's HTTP upgrade path, page-to-native-window relation, absence of TLS state, or absence of another writable clone. Those remain broker attestations.
8. [resolve_external_target](../../../vendor/niri/src/agent_input.rs:400) requires the current coordination revision, enabled/unlocked input, a mapped window with Wayland client PID, an existing seat, and `require_agent_client`. [require_agent_client](../../../vendor/niri/src/agent_input/shared.rs:41) rejects unresolved external effects, disconnected clients and human-owned applications, and applies existing agent conflict rules. It checks authority over the target application's Wayland client, not identity of the process controlling the agent seat. [require_capture_geometry](../../../vendor/niri/src/agent_input.rs:353) additionally checks compositor PID/start, current revision, output/placement and native window PID/rectangle.
9. Registration burns the intent ID, constructs only a masked `Page.navigate` frame and installs a writable calloop source plus expiry timer. [Writer::ready](../../../vendor/niri/src/external_admission.rs:128) runs on Niri's event thread, rechecks expiry, unresolved state, live target authority, capture geometry and browser generation, then performs one `send(MSG_DONTWAIT | MSG_NOSIGNAL)` without an await or library write queue. WouldBlock/Interrupted re-enters a later readiness turn with all checks repeated. Other errors, zero acceptance, partial acceptance and full frame acceptance are all unknown. Partial frames never send a remainder. Niri shuts down the write half and removes the writer source. [Writer drop](../../../vendor/niri/src/external_admission.rs:106) retires the pending count and reports refusal if admission never produced a report.

## Ordering and recovery limits

The enforceable admission point is the kernel send on the compositor actor. Human transitions use the same actor through [pointer/keyboard activity](../../../vendor/niri/src/agent_input/shared.rs:100), advance coordination and suspend conflicting agents. A takeover processed before the final send prevents it. A command accepted before takeover may apply in the application afterward. There is no application rollback or cancellation proof, and no guaranteed ordering based solely on when physical events arrived before actor processing.

The final authority path includes bounded `/proc` and geometry reads on the event thread. The FD send is nonblocking; this is not a measured human input latency guarantee or proof that host filesystem work can never stall. The existing target/client coordination rules are reused rather than bypassed.

[Unknown insertion](../../../vendor/niri/src/external_admission.rs:201) blocks external and native agent follow-ons for the target window across seats, fresh intents and new connections. `TargetKey` stores window, browser PID/start and compositor PID/start, but `external_target_unresolved` tests the window ID alone. No settlement or clearing path appears in the inspected sources. Fresh observation is necessary for recovery but cannot itself clear this compositor barrier. Compositor restart initializes this in-memory set empty; Pi's durable recovery must retain uncertainty across that restart. [Service result handling](../../../src/bin/dojo-agent/service.rs:740) marks unknown and drops its seat controller. A registration redesign must preserve these semantics and cannot silently use service restart to establish settlement.

## Narrow lazy registration design constraints

An admissible protocol would retain the current typed single-use writer and change only how a trusted broker generation is enrolled:

- Compositor startup has an explicit operator setting permitting this Rust desktop service to register. A new registration message must authenticate an operator-selected service identity independently of seat creation. A UID, PID supplied in JSON, socket pathname, `Hello.service_pid`, environment enable flag or arbitrary seat ownership is insufficient evidence.
- Capture kernel peer credentials on Niri IPC accept before async adaptation, resolve process start, and bind them immutably to ClientCtx and AgentSeat. A trusted registration binds exact process generation and permitted live peer IDs. Compare SCM sender credentials to that registration and the seat's owner. Multiple connections belonging to one process do not authorize guessing another process's peer.
- A registration must expire/revoke on process generation change, connection loss or compositor restart. New broker generation requires new authenticated registration. Queue validity remains tied to the owning live seat and current revision. Do not introduce a transferable permit for an external async CDP sink.
- Keep kernel FD checks, bounded request parsing, actor-built typed frame, exact final rechecks, one nonblocking send, expiry, burned intent IDs, close-on-partial and unresolved barriers. Keep broker-side compositor authentication before giving it a writable FD.
- Keep broker obligations for exact page/window/endpoint identity, permitted browser profile, internal authority and consent, retirement of previous browser connections, no surviving writable clone or buffered mutation, and no retry after an ambiguous handoff. FD transfer cannot prove exclusivity; the admitted Rust implementation remains trusted to honor it.

This can avoid predicting a lazy service PID at compositor startup. It introduces a new service identity trust boundary, whose proof must be at least as narrow as the current operator process pin. Recording seat-owner credentials alone is a useful prerequisite, not a complete replacement.

## Evidence and missing acceptance

Existing source tests cover frame restriction and malformed input at [external_admission.rs:668](../../../vendor/niri/src/external_admission.rs:668), real listener inode/process generation at [704](../../../vendor/niri/src/external_admission.rs:704), real credentials/FD close-on-exec at [714](../../../vendor/niri/src/external_admission.rs:714), takeover before the write at [849](../../../vendor/niri/src/external_admission.rs:849), unknown/no resend/cross-peer/native follow-on refusal at [874](../../../vendor/niri/src/external_admission.rs:874), and actual upgrade/FD registration/actor send at [945](../../../vendor/niri/src/external_admission.rs:945). Broker tests cover upgrade path/read-ahead and substituted compositor PID at [broker.rs:339](../../../crates/dojo-external-admission/src/broker.rs:339).

[SOCKET-PROOF.md](../../../crates/dojo-external-admission/SOCKET-PROOF.md) records a 2026-10-12 disposable nested run with primary-seat input and a held fixture effect. The [runner](../../../crates/dojo-external-admission/src/bin/nested-navigation.rs:117) launches a native fixture, uses fixed `PAGE-1`, and pins its own broker process before launching Niri. It proves the fixture actor/broker path, not live Chromium BrowserSession or MCP navigation parity. These tests and recorded runs were inspected, not rerun for this note.

Required missing route evidence includes a disposable real isolated Chromium profile, actual executable/root/native-client/listener/page/window correlation, browser read-only episode retirement, service lazy registration and generation restart, Pi committed intent through MCP to the final writer, human takeover before writable admission and while accepted navigation is pending, and durable recovery after missing receipts/service or compositor loss. Chrome subprocess identity must meet the existing exact-PID restriction or receive a separately proved adapter. Existing-profile consent, other CDP methods, general browser sockets, TLS/remote transport and AT-SPI mutation remain outside this narrow navigation proof.
