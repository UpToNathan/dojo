## Recommendation

Use **A as the interface and scope base**, graft **B's implementation-level evidence and reuse**: retain the complete coherent browser engine/contract privately if its embedded ownership seam passes, and adopt B's explicit compositor-peer, named-output, process-generation, cancellation, and capture-correlated scene requirements. Keep Pi as the only scheduler/durable run owner and Dojo's existing service/session as the only resource authority.

Do not adopt B's broad import as an established fact. Its own text says the source closure is not a build claim, and its proposed embedded constructor has not been shown to remove `legacy` scope, revive/reaper paths, ambient dispatch, or direct effect bypasses. Conversely, do not implement A's `SceneSource::capture_scene` as an independent call followed by a pixel capture: the design must return pixels and scene evidence tied to one compositor render/frame, or refuse window actionability. Niri stable `WindowLayout` or before/after IPC reads cannot substitute.

Keep all AT-SPI and browser external mutations refused until the ticket-16 admission point and in-flight/unknown semantics are actually demonstrated. A mutation lock, consent grant, or coordination-revision read does not grant human priority. Preserve capture consumption before effects, Niri's native dispatch rechecks, and Pi's no-replay recovery behavior.

## Next unit to execute

Neither candidate's next step is yet the right full implementation sequence. First run a bounded **embedded-core feasibility spike** inside the Rust runtime: vendor the pinned core/contract privately, compile the smallest `EmbeddedEpisode`, inject a unique Dojo episode key/liveness/cancellation context, disable legacy registration, and prove with direct bypass probes that closed/cross-session refs fail and no imported lifecycle path revives or publishes into a closed session. Audit every CUA action entrypoint for an innermost effect gate. This is a decision gate, not a production feature or an excuse to stop at planning.

If that spike passes without ambient-global exceptions, proceed with B's broad reuse while keeping the external API close to A's small surface. If it fails or requires pervasive lifecycle forks, use A's selective extraction path and import coherent modules only where their ownership/context can be adapted. In either case, next prove native named-output capture and scene-to-pixel correlation in Niri before advertising window-bound capture; then integrate AT-SPI and browser read paths. Keep CDP/D-Bus action routes unavailable until admission proof. Complete the Rust runtime and Pi durable cutover together before claiming adoption; the spike alone does not satisfy the user's full-adoption goal.
