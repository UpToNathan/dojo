# Perception integration decision

Use the contained worker candidate as the base. Both the root review and cross-judge prefer its process ownership and forced termination over embedded native inference. The scores are in `perception-crossjudge.md`; the stable candidate package is `candidate-worker/`.

The root scores the native candidate 4/1/4/3/2 and the worker candidate 5/4/4/4/5 for capture identity, cancellation and cleanup, interface depth, immutable packaging and implementation feasibility. The worker's draft contains more public types than callers need. Keep its backend and lifecycle types private, adapting the native candidate's single typed session operation.

Preserve the worker candidate's cold child, capacity refusal, exact immutable artifact/loader closure, off-loop service completion and final authoritative capture lookup. Reject detached embedded ONNX execution, stock CUA global capture/tool ownership and warm process reuse. Durable approvals are excluded from this implementation pending discussion.

The public tool name is exactly `parse_visual_regions`, as pinned in the Driver contract. Input schema comes from that manifest. A Dojo result carries the original capture digest, dimensions, named output and affine mapping; it must not invent a primary display. Options filter inferred regions, never action permissions.

Implementation proceeds without a design approval checkpoint. Actual models now exist and baseline Rust inference succeeds. Neither the standalone parse nor the design establishes contained service integration. The next implementation units are the session-owned read/completion gate, immutable loader package, cancellable cold adapter and keyed service completion, followed by real-model and live capture checks.
