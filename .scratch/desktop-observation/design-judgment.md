Choose design A as the base: keeping required `output` and adding optional `region`, `window_id`, and `scale` preserves existing calls and gives a small boundary/API. Enforce exactly one of region or window, and bound scale to 0.1–1.0. Keep region coordinates output-relative, clip against that output’s logical bounds, and translate using the output origin only where grim requires global geometry; this handles negative output positions without changing coordinate meaning. Keep resource budgets and clipboard/focus neutrality.

Neither proposal’s general Niri window-resolution path is implementable from current data. Tiled windows have `tile_pos_in_workspace_view: None`; scrolling `tiles_with_ipc_layouts` does not populate it. Floating positions are relative to the workspace view, not global, so they cannot be treated as output/global coordinates. Support window capture only for visible floating windows whose coordinates can be established correctly, and return a clear unavailable-geometry error for tiled or otherwise unpositioned windows. Do not infer bounds or switch focus/workspace. `grim -T` is also unavailable: the real compositor probe showed no screen-capture protocol support, and Niri IDs are not a substitute handle.

Design B’s tagged target and before/after geometry snapshot add API and implementation complexity without overcoming these missing coordinates. Graft its useful clipping/rounding and actual-image metadata ideas onto A, but defer snapshot comparison. Validate region and scale behavior with pure tests; compositor window capture remains limited by available geometry.
