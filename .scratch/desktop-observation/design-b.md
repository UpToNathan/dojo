# Capture plan with a tagged target

Keep `desktop_screenshot({"output":"eDP-1"})` valid. Add an explicit target form, for example `{"target":{"kind":"window","window_id":42},"scale":0.5}` and `{"target":{"kind":"region","output":"eDP-1","x":100,"y":80,"width":400,"height":300}}`. A tagged target makes the window and region requirements visible in the generated schema. It avoids an object with several unrelated optional selectors.

The boundary types in `dojo-agent.rs` are a strict, untagged `DesktopScreenshot` enum with two object variants: `Output { output: String, scale: Option<f64> }` for existing callers, and `Target { target: ScreenshotTarget, scale: Option<f64> }`. `ScreenshotTarget` uses `#[serde(tag = "kind", rename_all = "snake_case", deny_unknown_fields)]` and has `Output`, `Window`, and `Region` variants. Reject objects that mix legacy and tagged selectors. Check the emitted MCP schema, including the root object requirement already handled for `DesktopAction`. Accept finite scale values from 0.1 through 1.0 and default to 1.0.

The handler keeps its existing `spawn_blocking` call and passes the normalized target to `screenshot::capture`. Inside `screenshot.rs`, use three small types: `LogicalRect`, `CapturePlan { output, rect, scale }`, and a target-specific geometry snapshot for comparison. Their signatures are `resolve(target, snapshot, scale) -> Result<CapturePlan>`, `capture(socket_path, target, scale) -> Result<Vec<ContentBlock>>`, and `metadata(plan, png_dimensions) -> Value`. Resolution is pure; socket access and process execution stay in `capture`.

Resolve an output to its logical bounds. Resolve a window through `Window.workspace_id`, `Workspace.output`, and `Workspace.is_active`; reject missing geometry, inactive workspaces, disabled outputs, and fully offscreen tiles. Use `tile_pos_in_workspace_view` and `tile_size`, which Niri documents as the visual window bounds including decorations. Intersect with the output, round outward to integer logical bounds, and intersect again. Region coordinates are output-relative and receive the same clipping. Add `LogicalOutput.x/y` only when constructing grim's global `-g` geometry. Use `-o`, `-g`, and `-s`; never use Niri's clipboard-writing screenshot action or treat its window ID as grim's foreign-toplevel identifier.

Read source geometry before and after grim. Reject the result if its output placement, scale, transform, relevant workspace, or target bounds changed. Separate IPC reads cannot guarantee an atomic snapshot, so document that remaining race.

Every result includes output-relative logical origin, captured logical dimensions, actual PNG dimensions, and independent x/y logical-pixels-per-image-pixel ratios. Existing output captures have origin zero. Mapping uses origin plus image coordinate times ratio.

Tests cover strict selector parsing, scale bounds, clipping and outward rounding, inactive/offscreen windows, negative global output positions, metadata from actual PNG dimensions, and changed geometry rejection. Preserve existing timeout and PNG limits. A live check should compare output, window, and region captures while verifying unchanged focus and clipboard.
