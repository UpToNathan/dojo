# Browser lifecycle grounding

Source inspection on 2026-10-13. Upstream pin is `b4e4238742fa73daabfb664f1108113e9577849d` in `/tmp/dojo-browser-control-research-b4e4238`. This report proposes patch seams. It does not establish live cancellation or human takeover behavior.

## Conclusion

Reuse Browser Control's Playwright execution, extension and relay. Pi remains the task, model, durable intent and stop owner. A small lifecycle fork can stop commands for an exact session generation, retire its transports and reject delayed retries. That gives an enforceable extension-local stop after the extension processes revocation. It does **not** prove the stronger existing Niri rule that a mutation cannot start after compositor human takeover. Niri and Chrome execute in different actors; an asynchronous EventStream mirror has a propagation race. Keep that distinction explicit when selecting the mutation contract.

The native contract and its rationale are in [issue 16](/home/nathan/Dojo/.scratch/cua-adoption/issues/16-side-channel-admission.md). It requires queued effects to stop, immediate human input and unknown outcomes for already admitted effects. It explicitly rejects an ownership query followed by an external side effect as equivalent admission. A check at the beginning of `execute(code)` cannot stop later effects within that script.

## Upstream execution and ownership

`mcp.ts` registers execute and session operations. HTTP request disconnect aborts its Effect. `SessionManager.execute` acquires the session's execution semaphore in a detached worker, marks `started`, calls `sandbox.execute`, journals and persists completion. Caller interruption sets cancellation and interrupts the worker only before `started`. Once started the interrupt hook returns without stopping execution. Reset/delete use the execution lifecycle semaphore with a ten second timeout, so they are cleanup operations rather than emergency stop. [MCP registration](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/mcp.ts#L499), [HTTP close](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/http-api.ts#L276), [execute](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/session-manager.ts#L414), [detached work](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/session-manager.ts#L982).

`ExecuteSandbox` connects Playwright to the relay with the Browser Control session identity. `runUserCode` compiles an AsyncFunction and awaits it in the relay process. This is trusted Node code. Interrupting an Effect wrapping its Promise does not terminate arbitrary JavaScript, timers or Node side effects. Closing Playwright transport can cut off browser commands, but a malicious or accidental infinite synchronous loop can block the relay event loop. This is a trusted browser driver contract, not a general code cancellation guarantee. [Playwright connection](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/execute.ts#L782), [AsyncFunction](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/execute.ts#L2068).

The registry reserves and commits exclusive ownership of user-attached targets. Session target ownership distinguishes adopted user tabs from relay-created tabs. Release/reset must preserve adopted user tabs. The session ID is driver ownership, not authorization or compositor ownership. Raw CDP clients also exist, so a Dojo mode cannot enforce session retirement while leaving a sessionless bypass enabled. [Ownership registry](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/target-registry.ts#L232), [client admission](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/relay.ts#L794).

## Every queued command matters

Relay CDP routing resolves the client, target and child CDP session. Input methods and `DOM.scrollIntoViewIfNeeded` queue behind a per-tab semaphore. There are freshness checks before preparation and final forwarding, but they cover extension generation, target identity and socket routes. They do not check Niri ownership, canceled execution or a retired Browser Control generation. Preparation also invokes `beforeInput`, which can send additional commands; it needs the same gate. Non-input mutations such as Runtime evaluation and navigation do not pass the ordered-input freshness checks. [Routing and input queue](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/relay.ts#L1463).

`sendDebuggerCommand` forwards through a shared extension WebSocket. `ExtensionRpc.send` serializes a command with an ID and sends it immediately. Its interruption cleanup clears the response waiter; it does not retract bytes or send cancellation. `rejectDebuggerCommandsForTab` likewise rejects response waiters, not extension work. The pending record has a tab identity but no Dojo task/session generation. [Forwarding](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/relay.ts#L186), [RPC correlation and cleanup](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/extension-rpc.ts#L124).

The extension handles each WebSocket message asynchronously, calls `chrome.debugger.sendCommand`, and can recover debugger attachment and retry twice after certain errors. It can then fall back from `Page.navigate` to `chrome.tabs.update`. Revocation checks must precede the initial Chrome call, every recovery/reattach, each retry and fallback after awaits. Checking only on WebSocket receipt leaves queued continuation work alive. Socket-current checks currently mainly protect responses and selected grouping operations; they do not generally gate the debugger command branch. [Extension dispatch and retries](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/extension/src/background.ts#L457), [fallback](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/extension/src/background.ts#L162).

Already accepted Chrome commands may keep running after revocation. Runtime.evaluate can start page timers, event handlers, network requests or navigation whose later consequences are not new driver sends. Revocation cannot retract those effects. Record them as admitted/in flight or unknown, require fresh observation and prohibit automatic retry.

## Focus and human control

The tab request path focuses the browser window and activates the requested tab before showing the approval UI. Native browser tab identity does not establish the corresponding Wayland client connection. Chromium-family processes can expose several windows and renderer processes; PID alone is insufficient to prove the exact target. Dojo needs a proven browser-window-to-Niri-window mapping and generation before window-specific admission, or must conservatively stop all browser session mutations when any unbound human activity occurs. [Tab request focus](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/extension/src/background.ts#L1009).

Explicit handoff tracks an exact target's completion action; it is useful task UI but is not ordinary native-human takeover. The relay deliberately ignores toolbar detach while a session executes unless its handoff policy permits another action. A Dojo stop must override that executing-session restriction. Dojo should also control tab request focus and CDP/recording activation rather than unexpectedly move the user's active workspace. [Toolbar restriction](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/relay.ts#L1276), [handoff](https://github.com/anomalyco/browser-control/blob/b4e4238742fa73daabfb664f1108113e9577849d/src/handoff.ts).

## Dojo ownership and admission

Pi's `stop()` releases CUA and desktop clients before waiting on Pi storage, cancels human requests and computer step documents, then aborts its conversation. `close()` releases clients before closing the harness. The existing CUA extension uses a transport generation to refuse stale reconnects. Add browser release at these same early hooks, with relay session retirement rather than merely killing its stdio MCP child. Preserve Pi's durable task and intent ownership. [Pi lifecycle](/home/nathan/Dojo/tools/speech/pi-runtime.mjs:240), [CUA transport generation](/home/nathan/Dojo/tools/speech/cua-extension.mjs:31).

The desktop extension marks tools replay unsafe and sequential, persists attempts and capture consumption before dispatch, and has a durable unknown-effect barrier. Computer steps create an AbortController tied to Pi's signal and deadline; their phase transitions live in Rust and Pi documents. Reuse these intent/outcome rules for browser attempts. Do not import Browser Control's journal as a second durable task scheduler. [Desktop executor](/home/nathan/Dojo/tools/speech/desktop-extension.mjs:141), [bounded steps](/home/nathan/Dojo/tools/speech/computer-steps.mjs:36).

Niri owns input coordination by Wayland client connection. Pointer or keyboard ownership changes increment the revision; windows belonging to those clients appear in `human_owned_windows`. Native input checks this state in the compositor actor. `InputCoordination` is a snapshot and `EventStream` replicates initial state and later changes through a dedicated stream. The stream is appropriate for prompt retirement and UI state, not atomic external admission. [Coordination](/home/nathan/Dojo/vendor/niri/src/agent_input/coordination.rs:1), [IPC type](/home/nathan/Dojo/vendor/niri/niri-ipc/src/lib.rs:319), [stream initialization](/home/nathan/Dojo/vendor/niri/src/ipc/server.rs:276).

The external admission prototype resolves revision, live mapped window credentials, enabled unlocked agent seat and agent-client ownership. Its writer then checks exact process start, child/control lifetime, capture geometry and unresolved-effect barrier immediately before a nonblocking kernel send in the same actor as human input. It never awaits a Chrome reply there. Any accepted bytes create an unknown-effect barrier, and a partial write closes without retry. This proves an enforceable compositor admission point for its opt-in navigation route. It does not automatically work for the extension debugger API. [Exact target](/home/nathan/Dojo/vendor/niri/src/agent_input.rs:417), [final writer](/home/nathan/Dojo/vendor/niri/src/external_admission.rs:130).

## Concrete patch seams

1. Add exact session-generation retirement in upstream `SessionManager`, callable without the execute semaphore. Reject queued executes and reconnects, close all CDP client routes for that generation, cancel pending handoffs/network work and reject responses. Use a stable Pi-owned session identity with a new generation for each fresh task lease. Old session cleanup must not delete or adopt the new generation's targets.
2. Carry session, generation and command ID through `relay.ts`, `ExtensionRpc`, protocol definitions and extension dispatch. Keep revocation tombstones at the extension, including reconnect/service-worker restart policy. Fail closed until a current generation has been bound. Tag and gate helper commands, retries, tab create/remove/update, focus changes, network routes and any other mutation path. Treat Runtime evaluation as potentially mutating; upstream read-only mode blocks Input methods but is not DOM read-only.
3. Add a retirement acknowledgment that means the extension installed its tombstone and rejects future sends for the generation. Relay transport closure alone is not this acknowledgment. Classify existing Chrome calls as already admitted and unresolved where their completion is unavailable. Pi stop should request this path before ordinary cleanup and report unknown outcomes if acknowledgment is unavailable.
4. Subscribe to Niri EventStream in the Dojo browser bridge. On takeover, lock or stream loss, retire relevant sessions immediately. Map exact tab/window identity before narrower retirement. This bridge is execution plumbing only; Pi continues to schedule tasks.
5. Choose the actual human-priority contract explicitly. Extension-local checks guarantee rejection after extension revocation, with asynchronous takeover propagation and already-admitted effects documented. To satisfy issue 16's strict compositor ordering, send every admitted mutation through the compositor's same-actor gate, with exact destination/session identity and no reusable permit after the send. A compositor-issued lease followed by a later extension check still has the race. Adding an extension relay socket as the kernel-send destination moves enforceable admission to that send, so commands queued beyond it are already admitted, not retractably pending. This is only acceptable if the selected contract treats them as in flight and the extension still prevents follow-on work. It requires a proof for that actual route, not reuse of the TCP navigation fixture claim.

A small pinned lifecycle fork can deliver items 1 through 4 without rewriting Playwright or adding an agent runtime. Item 5 is a contract decision and proof boundary. If strict native ordering is required but the extension route cannot meet it, refuse those mutations. Do not label an event subscriber plus pre-execute check as meeting issue 16.

## Review and acceptance work

Use controllable boundaries at execute queue/start, Playwright send, relay input semaphore, beforeInput continuation, shared extension send, extension message receipt, recovery await, retry/fallback and Chrome completion. Retire at each boundary and assert that the retired generation sends no further command after its enforceable stop point. Exercise a long script that clicks repeatedly, not a single operation. Also test reused session IDs, adoption release, child target routes, sessionless clients, extension reconnect, Pi stop/close, stream disconnect and foreground focus behavior. Then repeat with actual nested Niri human input and an attached existing-profile tab. Record which sends preceded compositor takeover, which were admitted before revocation reached Chrome and which never ran. No rollback or no-post-takeover-effect claim follows from transport cancellation alone.
