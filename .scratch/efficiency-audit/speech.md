## Ranked findings

1. Prevent duplicate resident models before considering an unload policy. High confidence, high potential impact if the startup race occurs. `tools/speech/voice.mjs:352-355` starts a model worker before unconditionally unlinking and binding the voice socket. The systemd entry at `tools/speech/dojo-voice.service:9` invokes `--serve` directly. Only the CLI fallback at `tools/speech/voice.mjs:408-411` takes a flock. Therefore the two launch paths do not share singleton ownership. A shortcut during login before the systemd socket appears can start the fallback, and the systemd process can subsequently replace its socket while its model remains loaded. A systemd restart while a fallback server survives has the same ownership problem. This establishes a race, not evidence of current duplicates. The smallest fix is one lock held across the entire server lifetime on every entry path, acquired before `service.start()` and socket unlink. Verify simultaneous service and CLI startup with a stub worker, then check one voice server and one model process in a live session. This preserves prewarming and conversation continuity while removing redundant workers.

2. Stop writing the complete history for every streaming event. High confidence, medium impact, increasing with history and event rate. `tools/speech/voice.mjs:96-113` saves after every accepted subscription item. `message()` immediately ignores streaming assistant updates at line 117, yet the outer function still rewrites all state. `t3-client.mjs:10-14` creates a temporary file, JSON-stringifies the entire state and renames it. `voice.mjs:158` appends chats without a bound or archive, and `active()` searches that array at line 53. Consequently ignored updates still cause serialization, filesystem activity and queue work that grow with total history. The sequence advance is real state, so deleting all saves blindly would change recovery behavior. Smallest fix: persist important state transitions immediately and coalesce sequence-only changes with a final flush on completion, settlement and shutdown. Retain history/resume functionality; separate or archive old chat metadata if long-term growth proves material. Verify a burst of streaming events produces the final sequence and final message with a bounded number of writes, and restart recovery preserves pending dispatch and active run state.

3. Preserve the current subscription across follow-ups and use sequence replay when reconnecting. High confidence for duplicate subscription work; actual backend snapshot bytes are unmeasured. Every submit calls `watch()` at `voice.mjs:190`; `watch()` interrupts the current subscription at line 87 and starts another at line 88. It supplies no replay sequence even though `t3-client.mjs:97-100` supports `afterSequence` and `voice.mjs:102,111` records one. The snapshot path iterates all projected messages at line 99. The smallest fix is to remember the subscribed thread/client and leave a healthy same-thread subscription in place. On reconnect, use the recorded sequence where the protocol supports replay, while retaining snapshot fallback and ID deduplication. Verify two follow-ups use one subscription, reconnect receives missed events once, and replay expiry still restores a complete snapshot. Do not suppress follow-up context or settle the conversation sooner to save traffic.

4. Replace the permanent one-second voice interval with an idle deadline and close unused T3 connections. High confidence for wakeups and retained socket, unmeasured battery impact. `voice.mjs:383-394` schedules a permanent interval even when no chat or capture exists and the optional whole-service idle exit is disabled. Settlement unsubscribes at lines 305-306 but leaves `this.client` connected. The client answers server Ping frames at `t3-client.mjs:69`; server ping cadence is outside owned source. The smallest fix is one reschedulable deadline for the specified 30-second conversation interval, disarmed when there is no pending deadline. Close the voice WebSocket after settlement and reconnect on the next submit. Keep it open during active runs and within the follow-up interval. Verify a busy run does not settle, recording defers settlement, a follow-up before the deadline shares the thread, and an interaction afterward creates a new one. Count timer callbacks and traffic separately from actual battery measurements.

5. Decode screenshot dimensions without expanding every pixel. High confidence, medium per-tool-call opportunity. `src/bin/dojo-agent/screenshot.rs:64-72` fully decodes the captured PNG solely to read its width and height. Line 75 sends the original PNG unchanged. That decode adds pixel allocation and decompression on every screenshot; the 32 MiB compressed-file admission limit at lines 57-59 does not constrain expanded pixel memory. The smallest fix is an image decoder dimension query with explicit dimension/allocation limits. Preserve the original PNG, output selection and logical-coordinate mapping. Verify real screenshot dimensions and click-coordinate mapping remain identical, and malformed/excessive PNG headers fail cleanly. If full PNG integrity validation is desired, make that a deliberate boundary contract rather than assuming a dimensions query provides it. PNG capture, base64 expansion and model image processing remain separate costs.

6. Cancellation cannot stop or bypass in-flight transcription. High confidence, workload-dependent active energy/latency impact. `crates/dojo-speech/src/main.rs:145-167` reads commands and executes inference on the same thread. A cancel command cannot be read until inference finishes. The `cancel` branch at lines 173-177 only applies to a still-open capture, which finish has already taken. `lib.rs:173-177` checks its AtomicBool only around the full transcribe call. Voice immediately clears its capture on cancel at `voice.mjs:285-290`, so it discards the old result, but a fresh begin waits behind the old native inference. This wastes completed work for abandoned input and delays the next recording. The pinned `transcribe-cpp-0.2.4/src/session.rs:114-125` exposes `set_cancel_token`. Its native Parakeet family advertises cancellation in `transcribe-cpp-sys-0.2.4/src/arch/parakeet/capabilities.cpp:31-32`, but observation points depend on the actual run path. The smallest initial fix is per-request cancellation plus an input reader independent of the inference owner, checking cancellation between Hex chunks. Install the native token on every replacement session if the selected model supports it. Verify cancellation during inference, not just during capture, suppresses dispatch and allows another recording; measure abort latency on the actual unified model. Retain the warm model. The existing `scripts/check-speech-worker.py:33-38` covers capture cancellation only.

7. Reduce avoidable full-audio copies before redesigning capture. High confidence, low impact for brief push-to-talk clips, larger peak-memory impact for long clips. Capture accumulates native-rate mono data at `capture.rs:113-121`. `AudioClip::from_pcm` passes it by slice to resampling at `clip.rs:39`, which creates a new Recording and copies samples even at 16 kHz (`vendor/hex/src/dictation.rs:361-364,448-452`). `Transcriber::transcribe` then clones the normalized audio at `lib.rs:174` just to pad it. Long clips copy each inference chunk again at `vendor/hex/src/linux_transcriber.rs:172-174`. Smallest fix: move the validated Vec directly when rate/channels already match, borrow normalized samples when no padding is needed, and allocate only the short padded clip or final partial chunk. Preserve resampler quality and exact length semantics. Verify bit-identical 16 kHz input, stereo downmix, existing resampling fixtures, short-clip padding and chunk concatenation. Native-rate capture remains unbounded by design, so chunked resampling during capture is a separate larger option if sustained recordings matter. Do not silently cap recording duration or truncate speech.

8. Avoid nested devenv activation for the speech subprocess. High confidence that activation is repeated, unmeasured startup/process cost. The voice systemd unit already starts inside devenv at `dojo-voice.service:9`; `voice.mjs:238-241` starts another `devenv shell` to run the native worker. This repeats environment setup on model startup and crash recovery. Its justification is that CLI fallback may start outside devenv. Smallest fix: one maintained runtime wrapper/environment contract for the native binary, usable by both launch paths; invoke directly when the parent already supplies the required libraries. Verify startup outside devenv still loads audio/Vulkan libraries and the systemd path has no second environment activator. Prefer existing desktop wrapper patterns. Do not remove necessary library paths based on process count alone.

## Battery policy requiring measurement

The resident model is the largest candidate retained resource, but residency does not prove idle GPU power draw. `voice.mjs:51,236-242` eagerly starts it at login, `main.rs:140-145` loads once and waits on stdin, and `linux_transcriber.rs:106-111` selects `Backend::Auto`. The default model artifact is 731,357,568 bytes (`transcription_models.rs:250-255`), which is its on-disk size, not measured RAM or VRAM. `lib.rs:165` rehashes the artifact on load; native prewarming runs a silent 24,000-sample clip at `linux_transcriber.rs:151-156`. These costs repeat after unloading. The speech spec explicitly requires retaining the prewarmed model throughout the graphical session for fast activation.

Measure idle GPU runtime power state, RAM/VRAM residency, whole-system energy, cold startup and first-keypress readiness before proposing battery-driven unloading or CPU selection. If a live context prevents GPU suspension, the largest battery opportunity may be a power-aware speech-worker lifetime with a generous warm interval and explicit availability feedback. If the GPU already suspends with resident weights, unloading may save memory without meaningful battery savings and introduce latency. Smaller model selection and CPU inference also require real transcript quality and energy-per-successful-request comparisons. Keep agent conversations independent of worker lifetime. The existing `DOJO_VOICE_IDLE_SECONDS` exits the entire voice process and is unsuitable as a direct speech-only power policy; it is disabled by default and ordinary socket clients can launch a new server.

## Existing efficient choices

- No idle microphone or audio pre-roll. Capture owns CPAL only while recording and closes it before normalization (`capture.rs:87-111,129-131`). Its 25 ms timeout applies during recording, not all-day idle. The callback downmixes before transferring audio (`vendor/hex/src/audio.rs:743-772`).
- One verified model reused across recordings. SHA uses a bounded read buffer (`lib.rs:199-208`), and the package optimizes SHA in debug builds. Keep artifact verification unless a replacement preserves its integrity guarantee.
- Hex drops the used native session before constructing the next at `gguf_session.rs:65-78`, preventing retained input-sized scratch from pinning a long-run high-water mark. Do not restore permanent session reuse without proving native memory behavior.
- Voice defers assistant UI during capture, deduplicates displayed message IDs, limits seen IDs and UI preview length, and bounds local command input. It uses subscription events rather than polling T3 runs. Credentials are reused; issuing a new session is conditional, not per request.
- The agent MCP runtime uses a current-thread Tokio scheduler (`src/bin/dojo-agent.rs:472-476`). Observation tools do not allocate an input seat. The shared input service starts on action, blocks until events/deadlines (`service.rs:300-310`), drops idle controllers, and exits after a 250 ms empty grace. Its singleton lock already covers startup (`service.rs:259-263`). Preserve this behavior.
- Screenshots run only on explicit tool calls, select one output, bound compressed output size and have a five-second subprocess timeout. PNG and base64 are required by the current MCP image contract; format/resolution reductions need task-success validation.

## Evidence gaps and ownership

BLOCKED for claims of measured speedup, battery extension, current duplicate processes or actual GPU residency. The parent audit owns passive live measurements. No energy savings or performance percentages are claimed here. Code-based opportunity ranking is tentative until that evidence arrives.

Dojo owns its voice bridge, worker activation, state writes, subscriptions and desktop tools. T3 backend/provider processes, provider/model response cost, Electron runtime internals and server Ping policy are externally maintained. Distinguish their observed resource use from a defect in owned integration code.
